# Circuit-Issues-KiCad-OutputJob-Plugin

A KiCad 9/10 Action Plugin for generating common post-design outputs from one dialog.

## What it does

The plugin can generate:

- schematic PDF
- STEP 3D model
- Gerbers
- drill files
- position / PNP CSV
- BOM CSV files
- 3D render PNGs
- SVGs for visual diffs (schematic sheets, PCB layers, top/bottom views)
- ERC / DRC reports (run before the exports)
- JLCPCB output via the installed [JLC Plugin for KiCad](https://github.com/bennymeg/JLC-Plugin-for-KiCad)
- iBOM output via the installed [InteractiveHtmlBom](https://github.com/openscopeproject/InteractiveHtmlBom) plugin

## Main behavior

When started from KiCad, the plugin opens a configuration dialog where you can:

- choose relative output folders
- enable or disable exports
- choose a Gerber layer preset
- choose render sides
- set render quality and image size
- enable ERC/DRC checks and choose when they count as failed
- enable JLCPCB and iBOM integration

Settings are stored in a project-local file named `.kicad_plugin_config.json`.

## Output naming

Typical generated files:

- `myboard_SCH.pdf`
- `myboard_STEP.step`
- `myboard_POS.csv`
- `myboard_BOM.csv`
- `myboard_BOM_collapsed.csv`
- `myboard_PCBA_TOP.png`
- `myboard_PCBA_BOTTOM.png`
- `myboard_PCBA_LEFT.png`
- `myboard_PCBA_RIGHT.png`
- `myboard_PCBA_ISO1.png`
- `myboard_PCBA_ISO2.png`
- `doc/visual/schematic/myboard.svg`, `doc/visual/schematic/myboard-<sheet>.svg`
- `doc/visual/pcb/myboard-pcb-F_Cu.svg` (one per copper layer, plus `F_Silkscreen`, `F_Fab`, `top`, `bottom`)

Each run also writes `reports/summary.md`, `reports/summary.json`, `reports/erc.json`,
`reports/drc.json` and `reports/export.log` (relative to the project folder).

The BOM CSVs have the columns `Reference, Value, Footprint, MPN, Manufacturer, Quantity`.
`myboard_BOM.csv` has one row per reference; `myboard_BOM_collapsed.csv` groups parts with
the same Value + Footprint + MPN (`R1,R2` with quantity 2).

## Requirements

- KiCad 9 or KiCad 10
- `kicad-cli` available from KiCad installation
- wxPython available in KiCad's Python environment

Optional integrations:

- [JLC Plugin for KiCad](https://github.com/bennymeg/JLC-Plugin-for-KiCad)
- [InteractiveHtmlBom](https://github.com/openscopeproject/InteractiveHtmlBom)

## Install

Install the release zip with KiCad's Plugin and Content Manager ("Install from File..."), or
copy the plugin manually. The plugin folder is this repository: clone or copy it into the
KiCad scripting plugin directory:

| OS | KiCad 10 | KiCad 9 |
|---|---|---|
| Windows | `%APPDATA%\kicad\10.0\scripting\plugins\` | `%APPDATA%\kicad\9.0\scripting\plugins\` |
| Linux | `~/.local/share/kicad/10.0/scripting/plugins/` | `~/.local/share/kicad/9.0/scripting/plugins/` |

The result should look like:

```text
...\scripting\plugins\Circuit-Issues-KiCad-OutputJob-Plugin\__init__.py
...\scripting\plugins\Circuit-Issues-KiCad-OutputJob-Plugin\cli.py
...\scripting\plugins\Circuit-Issues-KiCad-OutputJob-Plugin\modules\...
```

For example: `git clone https://github.com/merlinmag/Circuit-Issues-KiCad-OutputJob-Plugin "%APPDATA%\kicad\10.0\scripting\plugins\Circuit-Issues-KiCad-OutputJob-Plugin"`.

## Usage

1. Restart KiCad after copying the plugin.
2. Open a board in PCB Editor.
3. Run `Circuit-Issues-KiCad-OutputJob-Plugin` from KiCad.
4. Select outputs and click `Save & Run`.

## Notes

- Output paths are relative to the project folder.
- Relative paths using `..` are allowed.
- Absolute paths are rejected.
- JLCPCB and iBOM outputs are generated by their own tooling and keep their own output conventions.
- Render time depends heavily on selected views, quality, and image size.
- ERC/DRC run first. Violations you excluded in KiCad (saved in the `.kicad_pro`) are not counted.

## Current integration defaults

The automated iBOM run is configured to:

- include tracks/zones
- include nets
- use `ibom` as output name format
- keep virtual component blacklist enabled
- keep empty-value blacklist disabled

## Headless / CI

The same exports run without KiCad's GUI, e.g. on an Ubuntu 24.04 CI server with KiCad 9 or 10
(`kicad-cli`) and optionally InteractiveHtmlBom installed:

```bash
python3 cli.py <project_dir | board.kicad_pcb> [--config PATH] [--only step1,step2] [--report-dir DIR]
```

`cli.py` works from the repository/plugin folder directly. If the folder is importable as a
Python package (a valid identifier, e.g. `outputjob/`), `python3 -m outputjob.cli ...` works too.

- **Config**: `--config PATH`, otherwise `<project>/.kicad_plugin_config.json` (the file the GUI
  saves), otherwise the bundled `config/config_defaults.json`. Missing keys are filled from the defaults.
- **Reports**: `--report-dir` (default `<project>/reports`) receives `summary.md`, `summary.json`,
  `erc.json`, `drc.json` and `export.log`. `summary.md` is meant as a commit message body: git short
  SHA, timestamp, per-step status (ok / failed / skipped + reason) with durations, ERC/DRC counts and
  the top violations.
- **`--only`**: run exactly these steps, regardless of their enable flags in the config. Steps:
  `erc`, `drc`, `schematic_pdf`, `step`, `gerbers`, `drill`, `position`, `bom_line_by_line`,
  `bom_collapsed`, `visual`, `render_top` ... `render_iso2`, `jlcpcb`, `ibom`; groups: `checks`,
  `sch_pdf`, `bom`, `renders` (the render views enabled in the config).
- **Exit codes**: `0` all OK, `1` an export failed (also used for usage errors such as a bad path),
  `2` ERC/DRC failed according to `checks.fail_on`. If both happen, `1` wins because the outputs are incomplete.
- Progress is printed as plain log lines.

### Checks

```json
"checks": {"erc": true, "drc": true, "fail_on": "error"}
```

ERC runs `kicad-cli sch erc`, DRC runs `kicad-cli pcb drc --schematic-parity`, both with
`--format json --severity-all`. `fail_on` is `"error"` (default), `"warning"` (errors or warnings)
or `"never"` (report only). Exports still run when the checks fail.

### Visual diffs

`"exports": {"visual": true}` writes SVGs with stable names (no dates) to `paths.visual`
(default `doc/visual`): one per schematic sheet in `schematic/`, and in `pcb/` one per copper layer
plus `F.Silkscreen` and `F.Fab`, and combined `top` / `bottom` (mirrored) views. Commit them and
GitHub shows changed images side by side. Stale SVGs from removed sheets/layers are deleted.

### Reproducible outputs

Creation timestamps are stripped from Gerbers (`%TF.CreationDate`, `G04 ... date`), the Gerber job
file, drill files, SVGs, the schematic PDF info dictionary and the STEP header, so a rerun on an
unchanged design produces byte-identical files. Known exception: STEP export through OpenCascade
can order style entities differently from run to run, so the STEP body may still change.

### Environment

| Variable | Purpose |
|---|---|
| `KICAD_CLI` | kicad-cli to use. Otherwise: `PATH`, the Windows install folders, `/usr/bin/kicad-cli`. |
| `KICAD_PLUGIN_DIRS` | Plugin folders to search for JLC/iBOM (`os.pathsep` separated). Replaces the built-in list (Windows `%APPDATA%`/Documents, Linux `~/.local/share/kicad/{9.0,10.0}/{3rdparty,scripting}/plugins`). |
| `IBOM_CLI` | `generate_interactive_bom` executable. Otherwise found on `PATH` or in the iBOM plugin folder. |
| `KICAD_PYTHON` | Python with `pcbnew` used for the headless JLC run (default: the current interpreter). |

- **3D renders**: on Linux without `DISPLAY`, render commands are wrapped in `xvfb-run -a` when it
  is installed (`apt install xvfb`). Without a display or xvfb a failing render is reported as
  `needs display/xvfb`.
- **iBOM** runs `generate_interactive_bom` with the same options as the GUI (tracks and nets included,
  name format `ibom`, virtual components blacklisted, empty-value blacklist off, no browser) into `<project>/bom/`.
- **JLCPCB** uses the JLC plugin's non-interactive mode in a separate Python process. If the plugin
  is not installed the step is reported as **skipped**, not failed.

### What to .gitignore in project repos

Commit the outputs you want to track (e.g. `manufacturing/`, `doc/`, `3d/`, `renders/`) and the
`.kicad_plugin_config.json` saved by the GUI, so CI uses the same settings. Ignore run artefacts:

```gitignore
# summary, erc/drc json and export.log, rewritten on every run
reports/
# local KiCad state that kicad-cli may create next to the project
*.kicad_prl
fp-info-cache
# optional: iBOM page and JLC plugin output, regenerated on every run
bom/ibom.html
production/
```

Older versions wrote `kicad_postdesign_export.log` to the project root; it can be deleted.

### Example GitHub Actions step

```yaml
- name: Generate KiCad outputs
  run: |
    set +e
    python3 plugin/cli.py hardware/
    code=$?
    git add -A hardware/manufacturing hardware/doc hardware/3d
    { printf 'Update KiCad outputs\n\n'; cat hardware/reports/summary.md; } | git commit -F - || true
    exit $code
```

## Development

Run tests from the repository root (the integration test is skipped when `kicad-cli` is missing):

```bash
python3 -m unittest discover -s tests -t . -v
```

The fixture project in `tests/fixtures/ci_fixture` (KiCad 9 format, 2 sheets, 5 parts, 2-layer board)
is generated by `tests/fixtures/generate_fixture.py`. Run the CLI on it with:

```bash
python3 cli.py tests/fixtures/ci_fixture
```
